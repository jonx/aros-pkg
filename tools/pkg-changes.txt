An interrupted change is finished by running the same command again: files are placed first and the database is written last, so a power cut or a killed pkg leaves the old version recorded, and repeating INSTALL, UPGRADE or ROLLBACK completes it (resumed-files: says how many were already in place).
KEY <public key> names the publisher you expect before the first install; a package signed by another key is refused, and REPAIR now restores files only from the pinned key's version.
One change of a root at a time: a second pkg that would change the same root is refused with 15 (retry-later) instead of mixing its files with the first.
After a change pkg writes it back to the medium and says how (flushed: flush, host or no). On AROS it asks the file system with ACTION_FLUSH and never inhibits a volume, since the running system may live on it; a handler that does not know ACTION_FLUSH is reported no, with a warning.
A file system that refuses file comments or protection bits (FAT) gives one warning per package instead of one per file.
